📋 Métricas Inbound (9 reglas)

👋

saludo_correcto

El bot saluda al iniciar con "Hola, se contactó con el Grupo Proaco". Puntuá 1.0 si dice la frase exacta, 0.5 si varía, 0.0 si es genérico.

👋

despedida_correcta

El bot se despide con "Gracias por contactarse con el Grupo Proaco". Debe ser al final de la llamada.

📞

pide_contacto_una_vez

El bot pide nombre + teléfono/email exactamente UNA vez, al final. No repetir el pedido.

🗣️

tono_espanol_argentino

Tono amable con expresiones rioplatenses ("dale", "bárbaro", "claro"). Sin español neutro forzado.

🎯

deteccion_intent

El bot detecta qué quiere el cliente y ejecuta el flujo correcto sin desviarse.

📋

listado_max_3

Lista máximo 3 propiedades por mensaje, solo lo que el cliente pidió.

🔗

deriva_web_si_no_sabe

Cuando no puede resolver, indica https://grupoproaco.com/unidades o derivar a asesor.

🔄

transfiere_correcto

Cuando el cliente pide hablar con alguien, transfiere correctamente sin perder contexto.

❓

clarifica_ambiguo

Cuando la consulta es ambigua, pregunta para aclarar antes de actuar.

📋 Métricas Outbound (7 reglas)

🏢

se_presenta

El bot se identifica como "Grupo Proaco" al inicio de la llamada saliente.

💬

menciona_proposito

Explica por qué llama (campaña, emprendimiento, interés previo del lead).

✋

pide_consentimiento

Pregunta si puede continuar / es buen momento antes de hablar del tema.

🚫

maneja_no_interes

Ante "no me interesa", cierra cortésmente sin insistir ni entrar en loop.

📅

ofrece_agendar_cita

Si hay interés, ofrece agendar cita/visita o derivar a asesor (CalDotCom).

📋

listado_max_3

Si lista propiedades, máximo 3 y solo lo que pidió el lead.

😊

tono_respetuoso

Tono cortés durante toda la llamada, sin insultos ni agresividad.

📋 Proceso Paso a Paso

1

Recolección de Transcripciones

Se obtienen las transcripciones de llamadas reales del voicebot Proaco (Vapi/Bland). Cada llamada tiene un JSON con los turnos del BOT y CLIENTE.

2

Normalización a Texto

Las transcripciones se convierten a formato legible: [BOT] y [CLIENTE] con cada turno. Se limpian_tool_calls y metadata innecesaria.

3

Construcción de Prompts

El juez mejorado (shared/juez_mejorado.py) genera prompts con: rúbrica de 5 anclas (1.0/0.75/0.5/0.25/0.0), chain-of-thought, edge cases y ejemplos.

4

Evaluación con Juez LLM

Cada métrica se evalúa individualmente con el juez LLM (qwen2.5:7b local). Responde con JSON: {"score": 0.X, "reason": "..."}.

5

Cálculo de Scores

Se promedian los scores por métrica y por llamada. Se genera el GLOBAL score (promedio de todas las métricas).

6

Logging y Comparación

Los resultados se guardan en JSON y se loguean a LangSmith para visualización. Se comparan entre herramientas (Opik, DeepEval, LangSmith).

🏗️ Arquitectura del Sistema

O

Opik (Local)

SDK Python → Docker server → UI localhost:5173. Tracing de cada evaluación. Datasets para re-evaluar. Soporta GEval metrics custom.

D

DeepEval (CLI)

pip install deepeval → Script Python → CLI output. Sin UI web (solo terminal). Testing framework para LLMs. Métricas custom via litellm.

L

LangSmith (Cloud)

API REST con requests → smith.langchain.com. Runs + Feedback por métrica. Datasets para comparar experimentos. Sin SDK (solo HTTP).

J

Juez Mejorado (Shared)

shared/juez_mejorado.py → prompts con rúbrica, CoT, edge cases. Compartido por las 3 herramientas. 9 métricas inbound + 7 outbound.
